# RPT — Remote Proxy Tunnel

Система удалённого доступа к роботам (SSH / SFTP) через центральный сервер с
веб-панелью в стиле Termius.

Роботы обычно стоят за NAT/файрволом и **сами** устанавливают исходящий
обратный SSH-туннель до центрального сервера. Администратор через веб-панель
подключается к любому роботу по **SSH** (терминал) или **SFTP** (файлы), при
этом весь трафик идёт по уже поднятому туннелю.

```
   ┌────────────┐   обратный SSH-туннель (-R)   ┌─────────────────────────┐
   │   РОБОТ     │ ────────────────────────────► │   ЦЕНТРАЛЬНЫЙ СЕРВЕР     │
   │            │                                │                         │
   │ sshd :22   │ ◄───── туннель порт NNNNN ──── │  hub (sshd для туннелей)│
   │ autossh    │                                │  backend (веб-панель)   │
   │ (docker)   │                                │       ▲                 │
   └────────────┘                                │       │ SSH/SFTP        │
                                                 │   Админ в браузере      │
                                                 └─────────────────────────┘
```

## 2. Где что лежит после установки

### На сервере
| Путь | Что это |
|------|---------|
| `/opt/rpt-server/`            | копия проекта server/ + `.env` |
| `/opt/rpt-server/.env`        | порты, пароль администратора, внешний адрес |
| `/usr/local/bin/rptctl`       | консоль управления сервером |
| docker volume `rpt-server_keys` | admin-ключ, host-ключ хаба, `authorized_keys` |
| docker volume `rpt-server_data` | база `rpt.db` (SQLite) |

### На роботе
| Путь | Что это |
|------|---------|
| `/opt/rpt-robot/`             | docker-compose проект туннеля |
| `/etc/rpt-robot/robot.env`    | статический конфиг (SN, имя, адрес сервера, порты) |
| `/etc/rpt-robot/runtime.env`  | результат сопряжения (порт, host-ключ хаба, токен) |
| `/etc/rpt-robot/tunnel_key`   | приватный туннельный ключ робота |
| `/etc/rpt-robot/known_hosts`  | host-ключ хаба (для проверки сервера) |
| `/usr/local/bin/rptctl`       | консоль управления роботом |
| пользователь `RM` (по умолч.) | под ним открывается сессия админа |

## 3. Установка сервера

На сервере (из каталога репозитория, от root):

```bash
sudo bash server-install.sh
```

Скрипт спросит:
- **внешний адрес/IP** сервера (его будут использовать роботы);
- **порт веб-панели** — любой свободный, **НЕ 80 и НЕ 443** (по умолчанию `8443`);
- **порт SSH-хаба** — к нему подключаются роботы (по умолчанию `2222`);
- **пароль администратора** веб-панели.

Дальше он поставит Docker (если нужно), развернёт проект в `/opt/rpt-server`,
поднимет контейнеры и покажет адрес панели.

> ⚠️ Откройте в файрволе TCP-порты: **порт веб-панели** и **порт хаба**.

Веб-панель: `http://<адрес-сервера>:<порт-веб-панели>`

## 4. Установка робота

Скопируйте `robot-install.sh` на робота и запустите **от root**:

```bash
sudo bash robot-install.sh
```

Скрипт спросит:
- **серийный номер** робота;
- **название** робота;
- **имя пользователя** сессии — по умолчанию `RM`;
- **пароль** пользователя — по умолчанию `536yfj67`;
- **адрес сервера**, **порт веб-панели**, **порт хаба**.

Что делает установщик:
1. создаёт пользователя `RM` с паролем и правами **sudo (NOPASSWD)** — чтобы админ
   через веб-терминал мог править файлы и запускать `sudo`-команды;
2. ставит зависимости (Docker, curl, jq, openssh);
3. включает `sshd` робота (в него заходит админ через туннель);
4. разворачивает контейнер туннеля в `/opt/rpt-robot`;
5. ставит консоль `rptctl`;
6. запускает **синхронизацию ключей** (см. ниже).

---

## 5. Синхронизация ключей (добавление робота «по кнопке»)

Это и есть механизм «нажал на сервере — нажал на роботе — принял подключение».

1. **На сервере** (веб-панель) нажмите **«🔑 Синхронизация ключей»**.
   Появится 6-значный **код сопряжения** (действует 10 минут) и адрес хаба.
2. **На роботе** выполните синхронизацию — это делает `robot-install.sh`
   автоматически, либо в любой момент вручную:
   ```bash
   sudo rptctl sync
   ```
   Робот сгенерирует туннельный ключ, спросит код и отправит заявку на сервер.
3. **На сервере** в разделе **«Ожидают подтверждения»** появится робот с
   кнопками **✓ Принять** / **✕ Отклонить**.
4. После **Принять** сервер:
   - назначает роботу свободный туннельный порт (диапазон 20000–20999);
   - добавляет туннельный ключ робота в `authorized_keys` хаба (с ограничением
     `permitlisten` — робот может слушать только свой порт);
   - возвращает роботу host-ключ хаба и свой **admin-ключ**.
5. Робот устанавливает admin-ключ в `authorized_keys` пользователя `RM` и
   поднимает обратный туннель. В панели он загорается **зелёным (онлайн)**.

Чтобы **переподключить** уже существующего робота (например, сменили сервер) —
снова `rptctl sync`, порт за роботом сохранится.

## 6. Работа в веб-панели

- **Список роботов** слева: имя, серийник, назначенный порт, заметки.
- **Индикатор статуса**: 🟢 зелёный — онлайн (туннель поднят), 🔴 красный —
  оффлайн. Обновляется автоматически каждые ~15 c.
- Кнопки на карточке робота:
  - **SSH** — открывает веб-терминал (xterm.js) прямо в браузере;
  - **SFTP** — файловый менеджер: навигация, ⬇ скачать, ⬆ загрузить, ＋ папка, 🗑 удалить;
  - **✎** — заметки и переименование робота;
  - **🗑** — удалить робота (его ключ убирается из хаба).

Терминал и SFTP работают под пользователем `RM`; `sudo` доступен без пароля.

| `rptctl rebuild`          | пересобрать образы и запустить |
| `rptctl set-port <порт>`  | сменить порт веб-панели (не 80/443) |
| `rptctl set-password`     | сменить пароль администратора |

### Робот — `rptctl` (или просто `rptctl` для меню)
| Команда | Действие |
|---------|----------|
| `rptctl sync`     | синхронизация ключей / (пере)подключение к серверу |
| `rptctl status`   | статус робота и туннеля |

| `rptctl logs`     | логи туннеля |
| `rptctl config`   | показать конфигурацию |

## 8. Как это работает под капотом

1. **Обратный туннель.** На роботе `autossh` держит соединение
   `ssh -R 0.0.0.0:<порт>:localhost:22 rtunnel@<сервер>` до хаба. Контейнер
   робота работает в `network_mode: host`, поэтому `localhost:22` — это `sshd`
   самого робота. Хаб слушает назначенный порт и переадресует его на робота.

2. **Хаб (`server/hub`).** Отдельный `sshd`, принимающий **только** обратные
   туннели от пользователя `rtunnel`. `authorized_keys` формирует backend: по
   строке на активного робота с ограничением `permitlisten="*:<порт>"`. Пароли и
   shell запрещены.

3. **Доступ админа.** Backend подключается к роботу как
   `RM@hub:<порт-робота>` по **admin-ключу** (asyncssh). Трафик проходит хаб →
   обратный туннель → `sshd` робота. Для терминала используется PTY поверх
   WebSocket, для файлов — SFTP-клиент.

4. **Онлайн-статус.** Backend раз в ~15 c проверяет, слушается ли назначенный
   порт на хабе. Дополнительно робот шлёт heartbeat каждые 30 c.

5. **Ключи.** `backend` при первом старте генерирует admin-ключ и host-ключ хаба
   в общем docker-томе `keys`. Host-ключ хаба выдаётся роботам, чтобы они
   проверяли подлинность сервера (`known_hosts`).

## 9. Безопасность (важно прочитать)

- Пароль `RM = 536yfj67` — значение **по умолчанию**. Смените его на роботах
  (`passwd RM`) для боевого использования.
- Пользователь `RM` получает `sudo NOPASSWD` — это сделано, чтобы веб-терминал
  мог запускать `sudo` без запроса пароля. Если это не нужно — удалите
  `/etc/sudoers.d/rpt-RM` на роботе.
- Веб-панель работает по **HTTP** (порт не 80/443). Для доступа из интернета
  поставьте её за реверс-прокси с TLS (например, Caddy/Nginx) или используйте
  VPN. Пароль администратора и cookie-сессии иначе идут в открытом виде.
- Backend ходит на роботов с `known_hosts=None` (host-ключ робота не
  проверяется): маршрут доверенный, целиком внутри инфраструктуры сервера.
- Туннельные ключи роботов ограничены `permitlisten` — робот не может занять
  чужой порт.
- Порт хаба открыт в интернет; вход только по ключу, shell и пароли отключены.

## 10. Диагностика

| Симптом | Что проверить |
|---------|---------------|
| Робот оффлайн (красный) | `rptctl status` и `rptctl logs` на роботе; открыт ли порт хаба в файрволе; правильный ли адрес сервера в `/etc/rpt-robot/robot.env` |
| Не подключается терминал | активен ли робот; `rptctl logs backend` на сервере; совпадает ли admin-ключ в `~RM/.ssh/authorized_keys` |
| Робот не появляется в «Ожидают подтверждения» | не истёк ли код сопряжения (10 мин); доступна ли веб-панель роботу (`curl http://<сервер>:<порт>/api/whoami`) |
| Ошибка host key на роботе | удалите `/etc/rpt-robot/known_hosts`, пересоздайте `sudo rptctl sync`, либо пересоздайте host-ключ хаба |
| Порты кончились | расширьте диапазон `RPT_PORT_START`/`RPT_PORT_END` в окружении backend |

Логи:
- сервер: `rptctl logs` (в `/opt/rpt-server`);
- робот: `rptctl logs` (в `/opt/rpt-robot`).

## 11. Требования

- **Сервер и роботы:** Linux с Docker + docker compose v2 (ставится автоматически).
- **Роботы:** установленный `openssh-server` (ставится автоматически).
- **Браузер администратора:** доступ в интернет для загрузки xterm.js с CDN
  (jsdelivr). Для полностью офлайн-среды положите файлы xterm рядом в `static/`
  и поправьте ссылки в `index.html`.
