# HelpDesk — служба поддержки (аналог Яндекс Трекера)

Веб-система заявок/тикетов, работающая в Docker. Поддерживает три языка
(**русский** — основной, **английский**, **中文**), администрирование с
подтверждением регистраций, права доступа к подразделениям, задачи со
статусами / приоритетами / исполнителями / комментариями / вложениями /
сроками, архив закрытых заявок и настраиваемую цветовую палитру.

> A helpdesk / ticketing system (Yandex-Tracker-style), running in Docker,
> with RU/EN/ZH localization, admin approval flow, per-department access
> control, full ticket workflow, archive and an admin-editable color palette.

## Возможности

- **Страница входа** с кнопкой регистрации и переключателем языка.
- **Три языка** (RU/EN/ZH). Выбранный язык **запоминается для пользователя**
  (в профиле на сервере + `localStorage`).
- **Нейтральная палитра**, которую администратор меняет прямо из интерфейса
  (раздел «Настройки оформления»); изменения применяются мгновенно ко всем.
- **Каталог подразделений** (например, «Поломойки»). Админ создаёт/переименовывает/удаляет их.
- **Задачи как в Яндекс Трекере**: ключ (`ПОЛО-1`), статусы
  (открыта → в работе → нужна информация → решена → закрыта), приоритеты,
  типы, исполнитель, срок, описание, **комментарии (переписка)**,
  **вложения**, **история изменений**.
- **Клиентская часть**: пользователь регистрируется (почта + пароль + описание).
  Администратор получает **уведомление**, **принимает или отклоняет** заявку и
  **выдаёт доступ** к конкретным подразделениям (выпадающий список + галочки).
- **«Взять в работу»** — назначить заявку на себя и перевести в статус «В работе».
- **Архив**: закрытые заявки автоматически уходят в архив и хранятся там.
- **Теги и фильтры (как в Трекере)**: цветные теги на заявках, создание тегов
  на лету, фильтрация списка задач по статусу / приоритету / типу / тегу / поиску.
- **Чек-листы внутри заявки**: подпункты с галочками и индикатором прогресса.
- **Email-уведомления (SMTP)**: письма при заявке на регистрацию (админам),
  одобрении/отклонении (пользователю), назначении исполнителя и новом
  комментарии. Работают в фоне и не блокируют интерфейс; если SMTP не настроен —
  просто отключены (внутренние уведомления в интерфейсе продолжают работать).
- **Вложения с просмотром на сайте (как в мессенджере)**: к описанию задачи и к
  каждому комментарию можно прикреплять файлы — фото, видео, скриншоты,
  документы (несколько сразу). Каждый файл показывается карточкой: превью,
  имя, размер и кнопка скачивания. Изображения и видео **открываются и
  проигрываются прямо на сайте** (видео стримится через HTTP range-запросы);
  клик по фото открывает его на весь экран. **HEIC/HEIF-фото с iPhone
  автоматически конвертируются в JPEG** при загрузке, поэтому открываются у
  всех. Лимит файла — `MAX_UPLOAD_MB` (по умолчанию 100 МБ).
- **Редактирование и удаление**: автор комментария (или админ) может изменить
  его текст (появляется пометка «изменено») или удалить комментарий целиком —
  вместе с его файлами. Любой прикреплённый файл (в комментарии или в секции
  «Вложения») удаляется кнопкой ✕ его автором или админом; файл стирается и с
  диска. Все действия попадают в историю задачи.
- **Чат (личные сообщения и группы)**: вкладка «Чат» в меню. Личная переписка
  (кнопка «✉ Написать» на карточке пользователя во вкладке «Пользователи»),
  групповые чаты с приглашением участников, аватаром группы и возможностью
  **прикрепить к группе существующие задачи**. В сообщениях — текст, фото,
  видео и файлы (просмотр прямо в чате). Справа от переписки — панель с
  **поиском по сообщениям** и вкладкой **«Вложения»** (все файлы чата), в
  группах дополнительно «Участники» и «Задачи». История переписки хранится в
  базе и попадает в бэкапы. Непрочитанные — красная точка в меню и у чата.
- **Аватарки**: в «Мой профиль» можно загрузить фото — оно отображается
  **кружком** везде, где встречается пользователь: список задач (исполнитель),
  комментарии, история изменений, чат, справочник сотрудников. Если аватарки
  нет — показывается цветной кружок с первой буквой имени (инициалом).
- **Адаптивность (мобильные устройства)**: интерфейс полноценно работает на
  телефоне в оригинальном масштабе — ничего не «съезжает». Боковое меню
  превращается в выдвижную панель (кнопка-гамбургер вверху), таблицы задач,
  пользователей и архива становятся аккуратными карточками «подпись → значение»,
  фильтры и формы разворачиваются на всю ширину. На ПК вид не меняется.
- **Сброс пароля администратором**: в списке пользователей кнопка «Сбросить
  пароль» задаёт временный пароль (можно ввести свой или сгенерировать). При
  следующем входе пользователь **обязан** сменить временный пароль на постоянный
  — появляется блокирующее окно, которое нельзя пропустить, пока не задан новый
  пароль. (Если настроен SMTP — временный пароль также уходит пользователю на почту.)
- **Должности (справочник ролей), на 3 языках**: администратор создаёт и
  редактирует названия должностей сразу в трёх вариантах (RU/EN/中文) и назначает
  их пользователям. Должность отображается на языке интерфейса пользователя.
- **Индикатор изменений (красный кружок)**: при новом действии в задаче
  (новый статус, комментарий, вложение, новая задача в подразделении) рядом с
  задачей, карточкой подразделения и пунктом «Каталог» в боковом меню загорается
  красный кружок. При открытии задачи её кружок гаснет; подразделение и «Каталог»
  гаснут, когда просмотрены все их задачи. Обновляется автоматически (опрос
  каждые 30 сек).
- **Вкладка «Пользователи» для всех**: отдельный от админской панели список всех
  сотрудников площадки. Каждый пользователь заполняет в своём профиле имя,
  должность и описание «о себе».
- **Персональные псевдонимы**: из этого списка любой пользователь может задать
  другому личный псевдоним и включить галочку «Отображать у меня». Псевдоним
  виден **только автору** и заменяет имя этого пользователя **везде** в системе
  (задачи, комментарии, история, исполнитель). Например, для учётки `孙浩` можно
  задать псевдоним «Сунь Хао» — и он будет отображаться так только у вас.
- **Роль «Наблюдатель»**: особая роль пользователя, которая **подсвечивается
  везде**, где он появляется — в списке задач, исполнителе, авторе,
  комментариях, истории и таблице пользователей (значок 👁 и жёлтая подсветка).
- **Экспорт / импорт всех данных (ZIP-архив)**: одной кнопкой скачивается
  полный бэкап-архив (открывается 7-Zip / проводником): внутри `data.json` со
  всеми данными (заявки, переписка, история, чек-листы, теги, пользователи,
  подразделения, настройки) и папка `uploads/` со **всеми загруженными файлами
  — фото, видео, документами — в оригинале**. Импорт архива полностью
  восстанавливает состояние, включая файлы на диске. Старые JSON-бэкапы тоже
  принимаются на восстановление.
- **Автоматические резервные копии по расписанию**: в админ-панели включается
  таймер (частота в часах + сколько копий хранить). Фоновый планировщик пишет
  ZIP-архивы в `/data/backups`, старые копии ротируются автоматически. Копии
  можно скачать или восстановить прямо из интерфейса.

## Быстрый старт (Docker)

```bash
cd helpdesk
cp .env.example .env        # при желании поменяйте пароль администратора и SECRET_KEY
docker compose up --build
```

Откройте <http://localhost:8000>.

**Учётная запись администратора по умолчанию** (создаётся при первом запуске):

- Email: `admin@helpdesk.local`
- Пароль: `admin12345`

Смените их через переменные `ADMIN_EMAIL` / `ADMIN_PASSWORD` в `.env`
**до первого запуска** (админ создаётся один раз, если база пуста).

### Настройка Email (по желанию)

Заполните SMTP-переменные в `.env`, чтобы включить письма:

```
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=login
SMTP_PASSWORD=secret
SMTP_TLS=true          # STARTTLS (порт 587); для SSL/465 задайте SMTP_SSL=true
MAIL_FROM=helpdesk@example.com
APP_BASE_URL=https://helpdesk.example.com   # для ссылок в письмах
```

Если `SMTP_HOST` пустой — email отключён, всё остальное работает как обычно.

## Как пользоваться

1. Войдите под администратором.
2. **Каталог → Новое подразделение** — создайте направление (напр. «Поломойки»).
3. Откройте подразделение → **Новая задача** — заведите заявку.
4. Пусть пользователь **зарегистрируется** на странице входа.
5. Админ: **Заявки на регистрацию** → **Принять**, выберите роль и отметьте
   галочками, какие подразделения пользователь может видеть.
6. Пользователь входит, видит доступные подразделения, открывает заявку,
   нажимает **«Взять в работу»**, ведёт переписку, меняет статус, прикрепляет
   файлы, ставит срок.
7. Перевод в статус **«Закрыта»** (или кнопка **«В архив»**) отправляет заявку
   в **Архив**.
8. **Настройки оформления** — измените палитру и название системы.

## Технологии

- **Backend**: FastAPI + SQLAlchemy (Python 3.12).
- **База данных**: SQLite по умолчанию (файл на volume). Легко переключается на
  PostgreSQL — задайте `DATABASE_URL` и раскомментируйте сервис `db` в
  `docker-compose.yml`.
- **Frontend**: одностраничное приложение на ванильном JavaScript (без сборки),
  палитра через CSS-переменные, i18n из JSON-словарей.
- Всё в одном контейнере; данные и вложения — в volume `helpdesk_data` (`/data`).

## Структура

```
helpdesk/
├─ backend/
│  └─ app/
│     ├─ main.py            # точка входа, монтирует статику фронтенда
│     ├─ models.py          # модели БД
│     ├─ schemas.py         # Pydantic-схемы
│     ├─ security.py        # хэш паролей, JWT
│     ├─ deps.py            # зависимости авторизации
│     ├─ seed.py            # создание админа при первом старте
│     └─ routers/           # auth, departments, tasks, comments, admin, notifications, settings
├─ frontend/
│  ├─ index.html
│  ├─ css/style.css
│  ├─ js/{i18n,api,app}.js
│  └─ i18n/{ru,en,zh}.json
├─ Dockerfile
├─ docker-compose.yml
└─ .env.example
```

## Разработка без Docker

```bash
cd helpdesk/backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL="sqlite:///./helpdesk.db"
export UPLOAD_DIR="./uploads"
export FRONTEND_DIR="../frontend"
uvicorn app.main:app --reload --port 8000
```
